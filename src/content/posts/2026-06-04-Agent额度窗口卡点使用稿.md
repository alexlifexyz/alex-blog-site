## 正文

各位用 Codex，或者各种 AI 编程 Agent 的老铁，今天不聊架构，不撕技术栈。

就分享一个很闷骚、很程序员、但真能救命的小操作：

**提前把额度窗口“点着”。**

你肯定见过那个场面。

代码写得正嗨，需求刚顺，Agent 正在帮你重构、补测试、查边界条件，突然屏幕上弹出一句冷冰冰的话：

> 当前额度已用完，请稍后再试。

那一刻，世界安静了。

你看着写了一半的逻辑，再看看自己退化回原始人的双手，突然不知道该干嘛。

以前没 AI 也能写代码。

但现在不一样。

你已经把一部分脑子外包给 Agent 了，它一断，你不是回到从前，你是半边脑子临时断网。

最气的是，它通常不是早上锁你，也不是睡前锁你。

它专挑下午三四点。

人在，咖啡在，状态在，需求也在。

只有你的赛博同事下班了。

## 破案了：很多人输在“第一条消息”太晚

很多 Agent 工具的使用限制，不是你想象中的“每天零点统一刷新”。

更常见的玩法，是按一段时间窗口来算。

以 Codex 这类工具为例，官方文档里就写得很清楚：Codex 现在更看重 credits 和 token 消耗，具体额度要看你的套餐、模型、上下文大小、任务复杂度，以及 Usage 面板里的当前状态。

翻译成人话：

你不是买了一个永动机。

你买的是一个会定时喘气的赛博工友。

问题就出在这里。

很多人下午 2 点正式开工，才给 Agent 发当天第一条重活：

> 帮我把这个模块重构一下，顺便补测试，顺便看看有没有边界问题。

系统一看，大活来了。

窗口开始跑，额度开始烧。

你 2 点开干，3 点半烧穿，接下来就只能看着提示面壁到刷新。

这就很亏。

你不一定是额度少到离谱。

很多时候，是窗口起点放得太晚。

## 骚操作来了：提前 3 小时 ping 一下

如果你每天真正高强度干活，是下午 2 点到 6 点。

那你别等下午 2 点才第一次叫醒 Agent。

**上午 11 点，提前发一条轻消息。**

比如：

```text
ping
```

或者：

```text
今天下午我要集中处理这个项目，先帮我记一下：稍后主要做重构和测试。
```

重点不是让它上午就开始爆肝。

重点是把使用窗口提前启动。

这样下午 2 点你正式开工时，窗口已经走了 3 个小时。

干到下午 4 点左右，上一段窗口差不多结束，新窗口有机会接上。

这时候别人正在终端前闭门思过，你这边刚好原地回血。

这不叫破解。

这叫尊重系统调度。

也可以叫：赛博卡点。

## 具体怎么配？

别每天定闹钟手动发。

这就不程序员了。

### Codex 用户

打开 Codex App，去左侧找 **Automations**。

新建一个自动化：

- 时间：每天上午 11:00
- 任务内容：发一条很轻的初始化消息
- 示例提示词：

```text
ping。今天下午我会集中处理当前项目，先不要做重任务，只记录一下稍后要进入工作状态。
```

注意，别让它扫描全仓库，别让它重构，别让它跑测试。

你只是点火，不是发射火箭。

### Codex CLI / 终端用户

如果你用 Mac 或 Linux，可以让它自己帮你写定时任务。

直接问 Codex：

```text
帮我写一个 macOS 的 launchd 或 crontab 定时任务，每天上午 11 点执行一条轻量 Codex 初始化命令，只发送 init，不做任何仓库扫描和代码修改。
```

如果你喜欢 crontab，大概就是这个方向：

```bash
0 11 * * 1-5 /usr/local/bin/codex exec "init。今天下午会集中编码，先记录工作状态，不要扫描仓库，不要修改文件。"
```

路径不一定一样。

你让 Agent 根据你本机的 `which codex` 结果改一下就行。

## 最后，别把小技巧用成自爆按钮

这个方法的本质，不是让额度凭空翻倍。

它只是把刷新点挪到你真正需要它的时间段。

如果你天天这么猛用，短窗口接上了，周额度也可能被你星期三直接干穿。

到时候就不是赛博卡 Bug 了。

是赛博闭门思过豪华版。

所以我的建议是：

平时正常用。

要重构、迁移、排疑难 bug、补一堆测试的那天，再提前 2-3 小时开窗。

好钢用在刀刃上。

AI 额度也一样。

学会了就去配一下。

别再下午 3 点半对着额度提示发呆了。

人还在上班，Agent 先请假，这种赛博冤案，能少一次是一次。

如果你还有更骚的 Agent 调教姿势，评论区见。
