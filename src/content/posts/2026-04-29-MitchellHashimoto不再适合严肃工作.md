Ghostty 为什么逃离 GitHub，那句“不再适合严肃工作”太扎心

4 月 28 日，Mitchell Hashimoto 发了一篇博客，正式宣布 Ghostty 会逐步离开 GitHub。

这事之所以有冲击力，不只是因为 Ghostty 是个热门终端。

更因为说这句话的人，是 HashiCorp 联合创始人，是 Vagrant、Terraform 的作者，也是 GitHub 用户 `#1299`。

他 2008 年 2 月加入 GitHub。

按他自己的说法，过去 18 年，他几乎每天都会打开 GitHub，而且一天不止一次。

所以这不是一个路人顺手发脾气。

他在文章开头就写得很直白：写这篇文章，让他有一种“非理性的悲伤”。

这种情绪我反而信。

因为后面那段更狠。

他说，过去一个月，他专门记了个日志。只要 GitHub 宕机影响到工作，他就在当天打一个 `X`。

结果几乎每天都有 `X`。

他写这篇文章当天，又碰上 GitHub Actions 出问题，PR review 直接卡了差不多 2 个小时。

然后他扔出一句很重的话：如果一个平台每天都把你挡在工作外面几个小时，它就已经不适合严肃工作了。

比起“Ghostty 要搬家”，我更在意这句话本身。

因为 Mitchell 不是在抱怨 Git 不好用。

他在脚注里专门补了一句：问题不在 Git，问题在围着 Git 的那一圈基础设施，像 issues、PR、Actions 这些东西。

因为今天大多数团队，真正卡脖子的就是这一圈东西。

代码当然能镜像。
仓库当然能迁。

可你每天真正在用的，很多时候根本不是那个 `git clone`。

你在用的是 PR 审核，是 CI，是 merge queue，是评论流，是权限系统，是 webhook，是那套把开发流程拧在一起的协作机器。

只要这套机器一天坏上几次，人就会被整个平台一起卡死。

Ghostty 这次搬家，扎心的点就在这。

一个对 GitHub 感情深到有点夸张的人，会决定搬家，原因其实很朴素。

不是审美，不是路线，不是 Microsoft，也不是哪条产品公告。

是“我今天又没法干活了”。

而且这件事，偏偏还是 GitHub 自己在同一天承认过的。

4 月 28 日，GitHub CTO 也发了一篇可用性更新。

里面直接承认，最近两次事故都不可接受。

更关键的是，GitHub 还公开说了一件很少有人会忽略的话：
从 2025 年 12 月下半月开始，`agentic development workflows` 的增长非常快。

他们原本从 2025 年 10 月就在做 `10X` 扩容。
到了 2026 年 2 月，发现未来得按 `30X` 的规模去设计。

仓库创建、PR 活动、API 调用、自动化任务、大仓库负载，都在往上冲。

这就很有意思了。

大家这半年都在喊 AI 写代码把开发效率拉上去了。
可另一边，承接这套流程的平台，开始被流量和自动化打得喘不过气。

你生成代码更快了。
你开 PR 更勤了。
你跑 Actions 更凶了。

结果平台顶不住，开发者照样被挡在门外。

这笔账，怎么都不算轻松。

所以我觉得，这件事不能只当成一个开源项目迁移新闻看。

它更像一个提醒：
过去那种“默认把所有开发协作都压在 GitHub 上”的习惯，开始变得有风险了。

尤其是活跃项目。
尤其是把 CI、review、发布、讨论全都绑死在一家的团队。

Mitchell 这次也没有搞得很戏剧化。

他已经说了，Ghostty 不会突然切断。
会渐进迁移。
现在的 GitHub 地址还会保留只读镜像。

他其他个人项目也先不动。
新平台也还没公布。

这恰恰说明，他不是在表演出走。

他只是很务实地承认了一件事：
再喜欢这个地方，也不能每天被它拦着干活。

对普通开发者来说，这事最值得抄下来的，不是“以后都别用 GitHub 了”。

而是另一句更冷的现实：
你以为自己依赖的是代码托管。
其实你依赖的是一整条在线协作流水线。

这条线一旦抖起来，项目不会立刻死。
但人会先烦死，团队会先慢死。

Ghostty 离开 GitHub，未必会掀起什么大迁徙。

但 Mitchell Hashimoto 这种用了 18 年、还对 GitHub 有感情的人都说出“不再适合严肃工作”，这已经够说明问题了。

开源世界最怕的，从来不是嘴上唱衰。

是连最忠实的老用户，都开始认真准备后路了。
