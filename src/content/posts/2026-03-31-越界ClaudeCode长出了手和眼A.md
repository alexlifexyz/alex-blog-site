### ■ 卢比孔河已被跨越

Anthropic 毫无预兆地向 Claude Code 的 Pro 和 Max 计划用户推送了一项名为“Computer Use（电脑使用）”的研究预览功能。

官方的更新日志非常短，但字字惊心：“Claude 现在可以打开你的应用，点击你的 UI，并在 CLI 中直接测试它所构建的内容。”

对于那些在前线跑 Agent 的开发者来说，这几行字意味着一件事：**AI 跨越了纯文本的沙盒，正式接管了你的操作系统。**

### ■ 闭环：自己写的代码，自己测

过去一年里，大模型写代码的能力突飞猛进。但传统的 AI 编程助手有一个致命的物理断层：它是个瞎子，而且没有手。
它能吐出完美的 React 组件，但无法知道这个组件在浏览器里到底长什么样、按钮点下去会不会报错。人类开发者只能充当那个可悲的“肉体中间件”——把 AI 写的代码跑起来，打开网页点击测试，然后再把报错信息复制回对话框。

现在，Claude Code 把这个“肉体中间件”给干掉了。

你让它写一个登录页面。它写完代码，会自动唤起你的 Chrome 浏览器，控制鼠标把光标移到输入框，输入测试账号，点击“Login”，然后捕捉屏幕的视觉反馈来验证自己的代码是否生效。
**它不仅有了手（操控键鼠），还长出了眼（屏幕视觉识别）。**

### ■ 降临派生存法则：当 CLI 拥有“上帝模式”

当一个跑在终端里的 CLI 工具能够随意调起你的本地应用、查阅你的 UI、甚至操控你的鼠标时，它就不再是一个简单的编程辅助工具了，而是一个拥有系统最高执行权限的数字幽灵。

大厂正在迅速把单向的文字生成器，升级为端到端的任务执行者。
这再次印证了我们之前在《a16z 应用笔记》里的判断：未来的软件交互是“无头（Headless）”的。大模型将不再需要你为了它专门去打开什么网页，它会直接潜伏在你的本地环境里，替你完成从开发到测试的完整重负荷劳动。

如果机器已经可以自己写代码，并能像真人一样打开浏览器自己测试代码，那只会堆砌语法、干体力活的初级程序员还剩下什么价值？

**别做那个“肉体中间件”。守住你的堆栈，提升你定义问题的能力。这比以往任何时候都更加紧迫。**
